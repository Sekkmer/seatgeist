# MCP Tools

Initial tool groups:

- Observation: `plasma.health`, `plasma.capabilities`, `plasma.list_monitors`, `plasma.list_windows`, `plasma.active_window`, `plasma.screenshot`, `plasma.screenshot_tile`, `plasma.observe`, `plasma.wait_for_change`.
- Control: `plasma.focus_window`, `plasma.type_text`, `plasma.key_combo`, `plasma.move_pointer`, `plasma.click_pointer`, `plasma.scroll_pointer`, `plasma.click_button`, `plasma.set_text_field`, `plasma.select_menu`, `plasma.activate_tab`.
- Clipboard: `plasma.clipboard_get_text`, `plasma.clipboard_set_text`.
- Accessibility: `plasma.a11y_focused_tree`, `plasma.a11y_find`, `plasma.a11y_invoke`, `plasma.a11y_set_text`.
- Safety/diagnostics: `plasma.policy_status`, `plasma.panic_stop_status`, `plasma.panic_stop_enable`, `plasma.panic_stop_disable`, `plasma.uinput_status`, `plasma.input_backend_status`, `plasma.pointer_calibration`, `plasma.journal_tail`.

All coordinate-bearing tools must require an explicit coordinate space. Full-resolution screenshots and clipboard reads are policy-gated and fail closed by default without explicit daemon approval.

Current daemon protocol exposes `observe`, `screenshot`, `screenshot-tile`, `wait_for_change`, window listing, active-window bridge reads, KWin bridge status, uinput status, input backend status, pointer calibration, panic-stop status/set, `focus_window`, `type_text`, `key_combo`, `move_pointer`, `click_pointer`, `scroll_pointer`, high-level `click_button`, high-level `set_text_field`, high-level `select_menu`, high-level `activate_tab`, clipboard text get/set, focused AT-SPI tree reads, AT-SPI find, AT-SPI invoke, AT-SPI set-text, and `journal_tail` through the CLI. The MCP stdio server exposes these current daemon-backed tools as `plasma.health`, `plasma.capabilities`, `plasma.policy_status`, `plasma.panic_stop_status`, `plasma.panic_stop_enable`, `plasma.panic_stop_disable`, `plasma.kwin_bridge_status`, `plasma.uinput_status`, `plasma.input_backend_status`, `plasma.pointer_calibration`, `plasma.list_monitors`, `plasma.list_windows`, `plasma.active_window`, `plasma.observe`, `plasma.screenshot`, `plasma.screenshot_tile`, `plasma.wait_for_change`, `plasma.focus_window`, `plasma.type_text`, `plasma.key_combo`, `plasma.move_pointer`, `plasma.click_pointer`, `plasma.scroll_pointer`, `plasma.click_button`, `plasma.set_text_field`, `plasma.select_menu`, `plasma.activate_tab`, `plasma.clipboard_get_text`, `plasma.clipboard_set_text`, `plasma.a11y_focused_tree`, `plasma.a11y_find`, `plasma.a11y_invoke`, `plasma.a11y_set_text`, and `plasma.journal_tail`.

`plasma.observe` returns monitors, windows, active-window state when available, and optional bounded screenshot metadata if `screenshot_output` is provided. If `full_resolution` is requested through `plasma.observe` or `plasma.screenshot`, the daemon classifies the request as full-resolution screenshot access and rejects it by default until started with explicit approval. Window and active-window objects include `monitor_id` when their logical geometry overlaps known KWin monitor geometry; active-window objects include pid when the KWin bridge publishes it. Tile coordinates are physical screenshot pixels. Screenshot responses include full source dimensions, output dimensions, source origin, scale factors, and monitor metadata when KWin responds; configured redaction regions are applied to the output PNG before metadata is returned. `plasma.wait_for_change` polls bounded screenshots until normalized RGB delta reaches `threshold` or `timeout_ms` expires; it returns changed/captures/elapsed/score metadata and the latest screenshot metadata. `plasma.kwin_bridge_status` reports whether the daemon DBus receiver registered, whether the KWin script has published an active-window update, and whether the user-local script package/config appear installed and enabled. `plasma.uinput_status` reports whether the daemon can open `/dev/uinput` read/write, whether the path exists and is a character device, mode/owner ids, daemon effective uid/gid, and a setup hint. `plasma.input_backend_status` probes xdg-desktop-portal RemoteDesktop, KDE portal service visibility, libei client metadata/socket hints, and uinput fallback availability without starting a portal session or sending input. `plasma.pointer_calibration` reports monitor-derived physical-pixel bounds, per-monitor physical origins, and representative sample points without moving the pointer. Focus, keyboard input, and pointer input are policy-gated control and are also blocked while panic-stop is active. Current control tools accept optional active-window guards: `expected_active_window`, `expected_active_app`, and `active_title_contains`. `plasma.type_text` types US-keyboard-mapped ASCII plus newline/tab through Linux uinput and reports text length only. `plasma.key_combo` sends named combos such as `Ctrl+L` or `Alt+F4` through Linux uinput and reports key count only. `plasma.move_pointer` and `plasma.click_pointer` require explicit `x`, `y`, and `coordinate_space`; current daemon support accepts `physical_pixel` and validates the point against monitor-derived physical desktop bounds, which supports 8K and scaled displays. `plasma.click_pointer` supports left/middle/right buttons and one or two clicks. `plasma.scroll_pointer` emits vertical and/or horizontal wheel deltas at the current pointer position. `plasma.click_button` finds a named non-sensitive AT-SPI button with optional app/window guards, invokes press only when exactly one viable match remains, and refuses ambiguous matches. `plasma.click_button`, `plasma.select_menu`, and `plasma.a11y_invoke` accept `destructive=true`; obvious destructive button/menu labels are also routed through destructive-action policy. `plasma.set_text_field` finds a named non-sensitive AT-SPI text field with optional app/window guards, requires one viable match, uses `EditableText` set-text, and reports replacement length only; secret-looking target names are routed through secret-field policy before matching. `plasma.select_menu` selects a visible AT-SPI menu path, such as `["File", "Open"]`, with optional app/window guards, requires one non-sensitive activatable item, and refuses missing or ambiguous paths. `plasma.activate_tab` finds a named non-sensitive AT-SPI tab with optional app/window guards, requires one viable match, and invokes select or press. Clipboard reads are policy-gated and fail closed by default until the daemon is started with an explicit clipboard-read approval mode. `plasma.clipboard_get_text` defaults to `max_bytes = 65536`, preserves UTF-8 boundaries when truncating, supports `full = true` for an explicit unbounded read, and returns backend provenance such as `wl-clipboard` or `kde-klipper`. `plasma.clipboard_set_text` uses the same local backend preference and reports backend provenance in action summaries without echoing content. `plasma.a11y_focused_tree` returns role/name/value/states/bounds/action names/children with `depth` and `max_nodes` caps; AT-SPI text values are capped at 512 characters and password roles suppress values. `plasma.a11y_find` filters by role, accessible-name substring, app name, and containing window name with result/depth/node caps. `plasma.a11y_invoke` invokes a normalized advertised action on an AT-SPI node id and is policy-gated as semantic control. `plasma.a11y_set_text` replaces non-sensitive `EditableText` contents, is capped at 8192 characters, and reports text length only in summaries. `plasma.journal_tail` supports `limit`, `method`, and `ok` filters. MCP tool responses return compact text plus structured JSON from the daemon; clipboard compact text and journal summaries report lengths rather than echoing clipboard content.

## Installation

Manual Codex config uses a stdio MCP server entry:

```toml
[mcp_servers.plasmapilot]
command = "plasma-pilot-mcp"
args = ["--stdio"]
```

The plugin bundle points at `plugin/.mcp.json` through `.codex-plugin/plugin.json`, so an installed plugin can provide the same MCP server config. The `plasma-pilot-mcp` binary must be on `PATH` for the current initial config.

The plugin bundle is validated by `make validate-plugin`, and the validator is included in `make verify`.
