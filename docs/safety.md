# Safety

Default rules:

- Observe is allowed; control defaults to prompt.
- Destructive semantic actions default to prompt and require a matching approval-file grant or explicit local allow policy.
- Clipboard reads default to prompt.
- Clipboard writes default to allow, but still flow through policy and the action journal.
- Secret/password fields default to deny.
- Full-resolution screenshots default to prompt and require a matching approval-file grant or explicit daemon approval mode before the backend capture path runs.
- Privileged input backends default to prompt.
- Focus guards should be supplied for pointer, keyboard, and semantic control actions whenever the caller has active-window context.
- Daemon requests are journaled as compact JSONL records with restrictive file permissions. Journal entries include explicit client tool identity from current CLI/MCP request envelopes when present, best-effort same-UID client pid/process-name metadata, safety class, guard/context metadata, and redacted control metadata such as action id, policy result, backend, coordinates, offsets, node ids, and text/key counts, but must not store raw request payload text, clipboard contents, semantic target names, or screenshot contents. Optional screenshot artifact path, byte-count, and SHA-256 metadata is disabled by default, is visible through `safety_status`, and requires `[journal].include_artifact_metadata = true`; image payloads are never stored in the journal.
- Daemon requests pass through the policy engine before execution; prompt-level decisions fail closed unless a configured approval file contains a matching unexpired method/safety-class grant.
- Accepted control-class requests are rate-limited by `[safety].control_rate_limit_per_minute`, which defaults to `120` over a rolling 60-second window. Observe/status requests are not counted.
- The daemon reads optional path and policy defaults from `~/.config/seatgeist/config.toml` or `--config` / `SEATGEIST_CONFIG`. Explicit CLI/env approval flags override file policy defaults for intentional local sessions.
- Approval files are opt-in through `--approval-file`, `SEATGEIST_APPROVAL_FILE`, or `[daemon].approval_file`; the daemon rejects approval files that are not regular files, not owned by the daemon uid, readable/writable/executable by group or other, or located in a parent directory writable by group or other.
- ScreenCast restore tokens are kept in a separate owner-only state file, keyed by a hash of the requested KWin target, atomically rotated, and never journaled or exposed through the protocol. Unsafe ownership, permissions, symlinks, or malformed content fail closed before the portal open; a different target cannot consume the token and uses ordinary portal consent.
- Retained capture and sticky interaction sessions are bound to the trusted same-UID Unix peer that opened them. MCP owners are process-scoped; verified CLI owners are tool-scoped for multi-invocation lifecycle commands. Renew, snapshot, wait, close, sticky raw actions, and post-action images fail with the non-oracular `session_owner_mismatch` kind before capture, focus, settle, or input side effects when the caller does not own the session.
- Retained-session execution status stores only sanitized backend names, method/action identifiers, safety and policy results, cooperative-focus and focus-lease outcomes, redacted activity provenance, and settle metadata. It never stores window titles, typed or clipboard text, accessibility values, portal credentials, or image content; read-only lifecycle calls cannot overwrite the last successful control action.
- Configured app deny rules block control-class actions before backend execution. If an app allow list is configured, control-class actions require a matching app id; deny rules take precedence.
- `[policy].destructive_actions` applies to requests explicitly marked `destructive`, exact `close_window` requests, known close/quit key combinations, and high-level button/menu labels that obviously imply delete, remove, discard, quit, shutdown, restart, or similar state loss.
- `[policy].secret_fields` applies to high-level text-field targets whose names look secret-related, and defaults to deny.
- `[safety].require_focus_guard = true` makes active-window guards mandatory for control-class requests before backend execution.
- `[safety].pause_on_human_input = true` blocks control-class requests when the trusted KWin activity tracker or configured legacy activity file is newer than `human_input_quiet_ms`.
- Sticky raw-input leases take a trusted activity snapshot before focus acquisition and check it again immediately before injection. Physical or unknown-provenance activity during the lease is journaled and aborts the action before any backend input; the legacy file signal cannot authorize automatic focus restoration.
- `[[safety.redact_regions]]` physical-pixel rectangles are mapped through screenshot output transforms and black-filled before screenshots leave the daemon.
- Replay traces are not a policy bypass: `seatgeist-cli trace validate` checks trace structure without contacting the daemon, and `seatgeist-cli trace replay` resubmits each recorded daemon request through the normal daemon socket, so control and clipboard-read requests remain policy-checked and journaled. Trace steps can assert expected error-message substrings for fail-closed paths and JSON-pointer equality, type, or existence for compact response metadata without exposing request payload contents or full response payloads in the replay summary; validation rejects empty/duplicate labels, unsupported JSON value types, and error expectations that conflict with a non-error response type or `ok=true`. Use `trace validate --dir` or `make validate-traces` for the daemon-free validation pass over every checked-in trace; empty trace sets fail instead of passing vacuously. Use `trace replay --dir` or `make smoke-trace-replay` to replay all checked-in traces against a private daemon. Use `examples/traces/status-smoke.json` for a safe status-only validation/replay smoke, including KWin bridge diagnostics, uinput access diagnostics, capture backend diagnostics, clipboard backend diagnostics, `input_backend_status.eis_keymap` metadata, and inactive retained EIS session status/stop responses; `examples/traces/policy-denials-smoke.json` to verify protected full-resolution screenshot, clipboard-read, focus-control, and AT-SPI text-control requests still fail closed before backend side effects; `examples/traces/input-denials-smoke.json` to verify raw keyboard, pointer, RemoteDesktop input-probe, EIS probe, and EIS start requests fail closed before backend side effects; and `examples/traces/panic-stop-smoke.json` to verify private-daemon panic-stop state transitions.
- Panic-stop is file-backed and checked inside the daemon after policy approval but before control execution; when active, it blocks control-class requests even if the daemon was started with `--allow-control`.
- Current control requests can carry active-window guards. When supplied or required by config, the daemon checks the active window id, app id, and title substring before control execution and rejects stale guards.
- Window resize is `ControlSemantic`, targets one explicit listed KWin id, applies app policy to that destination, is bounded to 64-32768 logical pixels per dimension, and is acknowledged by the packaged KWin bridge before success is reported. It never falls back to pointer dragging.
- Browser page zoom is `ControlKeyboard`, always requires an exact active-window id guard, rechecks that the active app is Firefox or Chromium-family immediately before input, and journals only operation/step metadata. It reports zoom steps rather than an unverifiable exact percentage.
- Keyboard input uses policy-gated `ControlKeyboard` requests, supports active-window guards, and journal/MCP summaries must report text length or key count rather than typed text.
- Retained independent-seat close/quit combinations such as `Alt+F4`, `Ctrl+W`, `Ctrl+Shift+W`, and `Ctrl+Q` are rejected before backend input even when the caller marks them destructive. Application-level shortcut routing cannot prove an exact window when several windows share a process. `close_window` instead requires the owned session and exact pinned KWin UUID, uses `DestructiveAction` policy, and has no keyboard fallback.
- MCP cannot call `focus_window` or launch with `activation=activate`. These requests fail before KWin control so model-driven work cannot change the physical user's active workspace window. Explicit CLI/operator focus remains policy-gated.
- Pointer input uses policy-gated `ControlPointer` requests, requires explicit coordinate space for move/click/drag tools, validates resolved physical-pixel coordinates against monitor-derived desktop bounds, supports active-window guards, and is blocked by panic-stop. `window_local` pointer coordinates are active-window-relative and always require an active-window guard before backend execution. `capture_output` coordinates additionally require an owned active retained session and its exact latest frame revision; they are transformed to the frame's source space only after policy/ownership checks, and stale or out-of-preview points fail closed.
- `wait_for_change` is observe-class and stores only compact delta/watchdog metadata in journal/MCP summaries by default, including whether the visual-change watchdog timed out before the threshold was reached. When journal artifact metadata is explicitly enabled, it may add the caller-requested bounded screenshot output path plus byte-count and SHA-256 metadata.
- An opt-in post-action image may read only an already-active retained session whose pinned KWin identity matches the explicit action destination. Validation happens before the side effect, capture start/finish are correlated to the action id, and the path never opens consent or falls back to a desktop screenshot.
- Screenshot v3 target requests are one-shot trait-backed sessions and never fall back to a full-desktop Spectacle capture after portal failure or cancellation. Expert `visible_window_crop_id` is the only window-crop compatibility mode: it is explicitly labeled `visible_window_crop`, reports occlusion risk, returns bounded window-local pixels, removes its temporary composed image, and fails closed when exact KWin/monitor geometry cannot be proven.
- Clipboard journal entries and compact MCP status text must not echo clipboard contents; `clipboard_status` should report only backend availability/setup metadata, and explicit clipboard reads should report text length/truncation metadata.
- Clipboard read tools should be bounded by default and require an explicit full-read option for unbounded content.
- AT-SPI password-text nodes are marked sensitive and excluded from current semantic action candidates.
- AT-SPI invoke is semantic control: it may only run through the policy engine and action journal, and defaults to prompt/deny when no matching approval grant is available.
- AT-SPI set-text is semantic control: it must reject sensitive nodes by default and journal replacement length rather than replacement contents.
- AT-SPI insert-text is semantic control: it must reject sensitive nodes by default and journal inserted-text length plus offset rather than inserted contents.
- AT-SPI delete-text is semantic control: it must reject sensitive nodes by default and journal only the deleted offset range, not deleted contents.
- AT-SPI copy-text and cut-text are semantic control: they must reject sensitive nodes by default, must not read clipboard contents after writing the selected range to the system clipboard, and must journal only offset ranges.
- AT-SPI paste-text is semantic control: it must reject sensitive nodes by default, must not read clipboard contents for the paste operation, and must journal only the paste offset.
- High-level semantic actions, including list/item selection, must refuse ambiguous matches instead of choosing one candidate implicitly; ambiguity errors should include bounded non-sensitive candidate choices so the caller can disambiguate.

The preferred human-input signal comes from the KWin `InputEventSpy` helper
documented in `docs/human-input-activity.md`. It reports only class,
provenance, seat, and monotonic timing. The file-backed signal remains a
compatibility fallback for pausing control, but it is never sufficient evidence
for automatic focus restoration.

Daemon runtime ownership keeps file-backed panic-stop state, the rolling
control-rate limiter, and private approval-file parsing together in
`crates/seatgeistd/src/safety_runtime.rs`. Request classification and policy
decisions remain in the daemon dispatcher; the runtime module only supplies
the stateful safety primitives used before backend execution.
