# PlasmaPilot Status

## 2026-07-04

Phase 0 scaffold is present:

- Cargo virtual workspace with resolver 3.
- Rust 2024 member crates for shared types, policy, backend traits, daemon, CLI, MCP, KWin, AT-SPI, and testkit.
- Conservative plugin, MCP, hook, skill, systemd, udev, and polkit skeletons.
- CLI and daemon are stubs; real socket RPC, screenshot, input, KWin, AT-SPI, and MCP protocol implementation remain future work.

Phase 1 first slice is implemented:

- `plasma-pilotd` binds a Unix socket, enforces restrictive socket directory/socket permissions, and rejects clients from another UID using Unix peer credentials.
- The daemon serves newline-delimited JSON requests for `health`, `capabilities`, and `policy_status`.
- `plasma-pilot-cli doctor`, `capabilities`, and `policy-status` call the daemon over the Unix socket.
- `make smoke` starts a temporary daemon, calls the CLI health/capability/policy commands, and verifies socket directory/socket modes.
- The daemon and CLI can capture a full-screen PNG through Spectacle when run in the host KDE session. The smoke capture on this workstation returned a 7680x4320 source image.
- Screenshot output now defaults to a bounded preview. On the 8K workstation, the default CLI screenshot produced a 1600x900 PNG with source/output dimensions and scale metadata; `--full-resolution` produced a 7680x4320 PNG with scale `1.0`.
- Spectacle captures are serialized inside the daemon because concurrent Spectacle captures can race.
- `plasma-pilot-cli monitors` now reports KWin monitor metadata from `org.kde.KWin.supportInformation`; on this workstation it reports `HDMI-A-2` as 5120x2880 logical at scale 1.5, matching the 7680x4320 screenshot source.
- Screenshot responses include the same monitor metadata when KWin responds.
- `plasma-pilot-cli screenshot-tile` can crop a physical-pixel region from the full Spectacle capture and optionally downscale the tile. A host smoke captured a 1600x1200 tile at source origin 3200,1600 and wrote an 800x600 PNG with scale factors 0.5.
- `plasma-pilot-cli windows` lists open windows through KWin's `WindowsRunner` and enriches each stable KWin window id through `org.kde.KWin.getWindowInfo` for title, app id, logical geometry, and monitor association derived from KWin monitor overlap. The current list path still reports `pid: null` because KWin's queried list surfaces do not expose per-window pid.
- `kwin/plasma-pilot-bridge` packages the PlasmaPilot KWin script. It reads KWin's `workspace.activeWindow`, subscribes to `windowActivated`, and publishes compact active-window JSON to the daemon over the session bus.
- `plasma-pilot-cli active-window` reads the daemon's latest KWin script bridge update. Before the script reports its first update, the command still fails with the documented bridge requirement because KWin's interactive `queryWindowInfo` is not suitable for unattended active-window checks.
- `make smoke-windows` validates window listing in a host KDE session and accepts either a real active-window bridge response or the documented bridge-not-yet-reporting failure.
- `make install-kwin-script` is available as an explicit, opt-in KWin configuration mutation for installing/enabling the script.
- The KWin script was installed on this workstation and a host smoke observed a real active window with app id, pid when published by the bridge, logical geometry, and derived monitor association through the daemon bridge.
- The daemon writes compact JSONL journal entries for every handled request. `plasma-pilot-cli journal tail --limit N` reads recent entries through the daemon, and smoke tests verify restrictive journal file permissions.
- Daemon requests now pass through the policy engine before execution. Current observe/status requests are allowed by default; any future prompt-level request fails closed until an approval channel exists.
- `plasma-pilot-cli focus --window <id>` focuses a listed KWin window through `WindowsRunner.Run`. It is a control action: default policy rejects it until a trusted approval channel exists, while `plasma-pilotd --allow-control` enables explicit local smoke/manual use.
- `make smoke-focus` validates the focus path in a host KDE session with `--allow-control` and confirms the focus request is journaled.
- `plasma-pilot-mcp --stdio` now implements the first MCP server slice: `initialize`, `ping`, `tools/list`, and `tools/call` for current daemon-backed observe/window/screenshot/focus/journal tools.
- `plasma-pilot-cli observe` and MCP `plasma.observe` return monitors, windows, active-window state when available, and optional screenshot metadata for a bounded preview capture.
- `make smoke-mcp` validates MCP initialize, tool discovery, daemon-backed `plasma.health`, and daemon-backed `plasma.observe` tool calls over stdio.
- `plasma-pilot-cli clipboard get|set` and MCP `plasma.clipboard_get_text` / `plasma.clipboard_set_text` now use the Wayland `wl-paste` / `wl-copy` backend for UTF-8 text. Clipboard reads remain prompt-gated by default and require `plasma-pilotd --allow-clipboard-read` until a trusted approval channel exists. Clipboard reads return at most 64 KiB by default, preserve UTF-8 boundaries when truncated, and include truncation metadata. Clipboard journal summaries report text length only.
- `make smoke-clipboard` validates the clipboard path with explicit clipboard-read approval, restores the previous clipboard text when it can read it, and removes temporary clipboard-content files.
- `plasma-pilot-cli atspi tree --focused` and MCP `plasma.a11y_focused_tree` now return a compact AT-SPI subtree rooted at the focused accessibility node. The first backend discovers the accessibility bus via `org.a11y.Bus.GetAddress`, walks application roots, detects focus from the AT-SPI state bitset, and reports role/name/states/bounds/action names/children with depth and node caps.
- AT-SPI node summaries now include bounded text/value summaries for nodes implementing `org.a11y.atspi.Text` or `org.a11y.atspi.Value`. Text reads are capped at 512 characters and report `value_truncated`; password roles are marked sensitive and values are not read.
- `plasma-pilot-cli atspi find` and MCP `plasma.a11y_find` now find compact AT-SPI nodes by role, name substring, application name, and containing window name with result/depth/node caps.
- `plasma-pilot-cli atspi invoke --node <id> --action <press|focus|select>` and MCP `plasma.a11y_invoke` now invoke advertised AT-SPI actions by resolving normalized actions to the node's `GetActions` index and calling `DoAction`. This is semantic control and remains denied by default until the daemon is started with an explicit control approval mode.
- `plasma-pilot-cli atspi set-text --node <id> <text>` and MCP `plasma.a11y_set_text` now replace non-sensitive `EditableText` contents through `SetTextContents`, cap replacement text at 8192 characters, and journal only text length.
- `plasma-pilot-cli semantic click-button --name <name>` and MCP `plasma.click_button` now implement the first high-level semantic action. The daemon searches AT-SPI buttons with optional app/window guards, requires a single non-sensitive pressable match, refuses ambiguity, and invokes the matched button through the same policy-gated semantic control path.
- `plasma-pilot-cli semantic set-text-field --name <name> <text>` and MCP `plasma.set_text_field` now implement high-level text-field mutation. The daemon searches non-sensitive AT-SPI text fields with optional app/window guards, requires a single viable match, refuses ambiguity, calls `EditableText` set-text, and journals only replacement length.
- `plasma-pilot-cli semantic select-menu --path File/Open` and MCP `plasma.select_menu` now implement visible AT-SPI menu-path selection. The daemon requires at least one path segment, searches visible menu hierarchy nodes with optional app/window guards, requires one non-sensitive activatable item, refuses missing or ambiguous paths, and invokes select or press.
- `plasma-pilot-cli semantic activate-tab --name <name>` and MCP `plasma.activate_tab` now implement high-level tab activation. The daemon searches non-sensitive AT-SPI tab nodes with optional app/window guards, requires a single viable match, refuses ambiguity, and invokes select or press.
- `make smoke-atspi` validates the daemon-backed focused accessibility tree, accessibility find paths, and deny-by-default accessibility invoke/set-text/click-button/set-text-field/select-menu/activate-tab paths, and confirms the requests are journaled.
- `crates/plasma-pilotd/tests/protocol_integration.rs` now starts a real daemon binary on a private Unix socket and verifies health, policy, capabilities, and journal-tail responses over the newline JSON protocol.
- `crates/plasma-pilot-cli/tests/daemon_cli_integration.rs` now starts a real daemon binary and verifies that the actual CLI binary can call `doctor`, `capabilities`, `policy-status`, and `journal tail` over a private Unix socket.
- `plasma-pilot-testkit` now provides deterministic mock implementations of the screen, window, input, clipboard, and accessibility backend traits, including call recording for future unit tests that must not touch the real desktop.
- `ScreenshotTransform::output_to_source_point` maps downscaled screenshot output coordinates back to source coordinates, with protocol tests for 8K preview and physical-pixel tile calibration.
- `scripts/gui-eval.sh` and `make gui-eval` run opt-in local evals against a private daemon socket for current non-control flows: status, observe, default clipboard-read denial, bounded screenshot preview metadata, and journal output.
- `ReplayTrace` and `plasma-pilot-cli trace replay --file <path>` provide replayable daemon-request traces with expected response metadata; replayed steps still flow through daemon policy enforcement and journaling.
- `plasma-pilot-cli panic-stop status|enable|disable` now controls a daemon-side file-backed panic-stop flag. The daemon journals these requests and rejects control-class actions while the flag is active, even when control policy is explicitly allowed.
- MCP now exposes `plasma.panic_stop_status`, `plasma.panic_stop_enable`, and `plasma.panic_stop_disable` through the same daemon-backed panic-stop protocol.
- `plasma-pilot-cli journal tail` and MCP `plasma.journal_tail` now support method and success filters for compact troubleshooting, for example `--method focus_window --ok false`.
- Current control requests now support optional active-window guards. CLI/MCP callers can pass expected active window id, app id, or title substring; the daemon rejects the request before execution if the active window no longer matches.
- `plasma-pilot-cli wait-for-change` and MCP `plasma.wait_for_change` now poll bounded screenshots, compute normalized RGB delta against a baseline, and return compact changed/captures/elapsed/score metadata with the latest screenshot metadata.
- `plasma-pilot-cli kwin-bridge-status` and MCP `plasma.kwin_bridge_status` now report daemon DBus receiver state, whether a bridge update has been seen, and user-local KWin script package/config installation state.
- `plasma-pilot-uinput` now provides an initial Linux uinput keyboard backend. `plasma-pilot-cli input type-text`, `plasma-pilot-cli input key-combo`, MCP `plasma.type_text`, and MCP `plasma.key_combo` send policy-gated `ControlKeyboard` requests through the daemon; panic-stop and active-window guards apply, and summaries report text length or key count only.
- `plasma-pilot-uinput` now provides an initial Linux uinput pointer backend. `plasma-pilot-cli input move-pointer`, `click-pointer`, and `scroll-pointer`, plus MCP `plasma.move_pointer`, `plasma.click_pointer`, and `plasma.scroll_pointer`, send policy-gated `ControlPointer` requests through the daemon; panic-stop and active-window guards apply. Move/click require explicit `physical_pixel` coordinates and validate them against monitor-derived physical bounds for scaled 8K layouts; click supports one or two left/middle/right clicks, and scroll supports vertical/horizontal wheel deltas.
- `plasma-pilot-cli input status`, MCP `plasma.uinput_status`, and `make smoke-uinput-status` now provide safe uinput access diagnostics without sending input. The status reports `/dev/uinput` availability, character-device state, mode/owner ids, daemon effective uid/gid, and a setup hint. `docs/uinput-setup.md` documents the optional udev rule, user service setup, current polkit placeholder state, and safe smoke flow.
- `plasma-pilot-cli input backends`, MCP `plasma.input_backend_status`, and `make smoke-uinput-status` now provide safe portal/libei/uinput backend probes without starting a RemoteDesktop session or sending input. The probe reports xdg-desktop-portal RemoteDesktop interface visibility, KDE portal service visibility, libei client metadata/socket hints, uinput fallback availability, and the currently preferred visible backend.
- `plasma-pilot-cli input pointer-calibration`, MCP `plasma.pointer_calibration`, and `make smoke-pointer-calibration` now provide safe pointer calibration diagnostics without moving the pointer. The response reports physical-pixel bounds derived from KWin monitor metadata, per-monitor physical origins, and representative top-left/center/bottom-right sample points for guarded GUI smoke.
- `make smoke-gui-input` now validates real policy-gated uinput control in a disposable KWrite/Kate document. It starts a private daemon with explicit control approval, focuses the test window through KWin, requires an active-window guard, maps a safe window point to physical pixels through pointer calibration, clicks, types a sentinel, saves, verifies file content, and checks the journal.
- The host GUI smoke exposed and fixed the initial keyboard mapping bug where text typing assumed evdev letter codes were contiguous; the uinput backend now uses explicit US evdev letter mappings.
- Actual portal RemoteDesktop/libei control backends, richer AT-SPI edit operations, remaining high-level semantic actions, portal/KDE-native clipboard fallback, and portal/KWin-native capture backends remain future work.
